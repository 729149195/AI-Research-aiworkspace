# 自建 Overleaf 与本地同步（内置 CE 直连）

**新项目默认使用 AI Workspace 内置 Overleaf Community Edition 传输，无需 VS Code、Cursor、Overleaf-Workshop 或 Git Bridge。** 自建物理机继续运行原有 Overleaf CE；大模型由本地文件型 Agent 提供，服务器无需安装 AI 插件。

本指南基于 main 的 `6f76f48`（内置 CE 传输）与 `e357aad`（远端新建项目），当前包版本为 0.6.1。研究目录迁移尚未完成，实际论文仍使用 `workspace/` 和 `manuscript/<subdir>`。不要按目标架构图搬动旧论文。

## 1. 准备本机 Agent

安装并登录你有权使用的本地 Agent，例如 Codex 独立客户端或 Claude Code。需要本地文件、命令执行和联网权限；纯网页聊天无法完成电脑上的配置。模型选择、账号和使用费用由 Agent 宿主管理。

打开 [AI Research Workspace 仓库](https://github.com/729149195/AI-Research-aiworkspace)，使用 Code → Download ZIP 下载并解压到独立文件夹，或让 Agent 克隆仓库。已有版本请通过 [增量更新](UPDATING.md) 核对后更新，保留旧稿。

在 Agent 中打开完整框架文件夹，说：

> 请读取根目录 AGENTS.md，检查当前版本并显示 AI Workspace 菜单。使用内置 Overleaf CE 直连，不安装编辑器插件；需要准备环境时先告诉我。

Agent 检查 Python 3.11+、独立虚拟环境、`overleaf-ce` 可选依赖（websocket-client）。缺失时先确认再安装；用户无需手工填写 JSON、输入命令或设置项目 ID。

## 2. 选择本地论文和远端项目

在浏览器打开实验室 Overleaf：[https://nankaivisoverleaf.asia/](https://nankaivisoverleaf.asia/)，用自己的实验室账号登录。确认能打开目标论文，并有需要的编辑权限。其他自建服务器使用自己的 HTTPS 地址。

已有论文时，从浏览器复制普通项目链接（形如 `https://nankaivisoverleaf.asia/project/项目ID`，不要复制含共享密钥的邀请链接），然后告诉 Agent：

> 选 6。请使用内置 CE 直连连接这篇论文：[项目链接]。帮我建立独立的本地论文项目或复用已有工作区，保留原稿，先预览首次拉取的范围，不覆盖任何已有文件。

没有远端论文时：

> 请在实验室 Overleaf 新建名为“我的论文”的空白项目，使用内置 CE 直连，与本地研究工作区建立绑定。创建前请让我确认。

Agent 负责初始化或复用真实论文根目录，并选择已有的稿件子目录。首次拉取已有远端论文时优先使用空的 `manuscript/<subdir>`；框架仓库本身不初始化为论文，不向公共 GitHub 上传真实论文。已有本地稿和远端同时非空时，应先备份并核对差异，遇到同名冲突暂停。

## 3. 登录内置 CE

在 Agent 指引的本机交互式终端输入 Overleaf 邮箱和密码（密码隐藏输入），或按宿主支持的安全方式本人完成认证。若 Agent 不能操作交互终端，应请用户在本机完成该登录步骤。原始密码不保存；会话 cookie 保存在该论文的 Git 忽略目录 `.rw/overleaf/ce-session.json`，在支持的系统上限制文件权限。

不要把密码、token、cookie 发给聊天，不要提交到 Git，不允许 Agent 读取浏览器的私有凭据库。若服务器使用 SSO 或验证码，按正常流程本人完成认证，再由本机安全会话环境接入；不绕过验证码，不禁用 TLS 校验。会话失效时重新登录。

## 4. 预览并完成首次同步

> 请检查已登录的服务器和项目 ID，预览内置 CE 同步差异。确认只有选定稿件目录，原稿不被改写；得到我的确认后执行首次同步。

Agent 列出本地/远端差异、同步目录和冲突。确认目标正确再执行。原始 LaTeX 文件名、层次、图表和参考文献保持原样；只同步选定稿件范围内支持的源文件。研究笔记、规则、原始数据、内部状态与凭据留在本地。旧引擎的 LaTeX 语义接入仍有目录/标记限制；首次文件同步无需为满足旧接口而合并章节、插入标记或重建稿件。

完成后应能在本地看到实际主文件、章节、图片和参考文献，并与网页版核对。检查结果有冲突或同步中断时，保留两侧文件，由 Agent 检查恢复状态，不盲目覆盖、强制删除或重建基线。

## 5. 验收真实连接

> 请先进行内置 CE 只读验收，核对主文件、项目身份与本地文件；经我确认后执行一次临时文件的双向收发测试，清理临时文件并确认原稿未变。

| 看到的结果 | 含义 |
|---|---|
| 已配置或会话已保存 | 仍需真实联网验收 |
| readable_via_ce | 远端项目可读；核对主文件匹配结果，尚未验证写入 |
| roundtrip_verified | 一次随机 PNG 的上传、远端覆盖、读回、清理通过，检查范围内本地原稿未改变 |
| incomplete、冲突、超时 | 验收未完成；说明具体步骤，保留现场 |

探针经授权才写远端，不引用论文正文，仍可能留下项目历史。它验证的是内置 CE 的二进制通信与清理；随后应在明确授权的试验项目或实际改稿中核对本地到网页、网页到本地的正文变化。它不证明任意文件、长期实时稳定性或科学结论正确。只读验收无需创建测试文件。没有实际回执不能说连接通过。

## 6. 远程编译与日常使用

> 请在确认差异并完成同步后，使用内置 CE 触发远程 LaTeX 编译，下载 PDF 和日志，检查编译结果。

Agent 使用服务器的编译设置，成功后取回 `.rw/builds/<build_id>/output.pdf`，若服务返回日志则同时保存 `output.log`。不必另装本地 TeX 来执行远程编译；网络、服务器 TeX 环境及原稿错误可能影响编译。核对实际 PDF，不能仅凭命令退出状态判定论文已可投稿。

之后直接说“修改摘要并同步”“拉取导师在网页上的改动”“检查项目进度”。内置引擎通过 HTTPS、Socket.IO/UTF-16 OT 和二进制上传执行同步，并维护三方合并基线；语义核对及科研状态更新由 Manuscript Sync/auto-route 负责。

默认在 Agent 发起时执行一次同步，不会随安装自动启动后台服务。需要持续监测时，经明确授权由 Agent 启动前台轮询并说明如何停止；冲突、进程关闭、会话过期或网络中断时检查状态后恢复。

## 7. 常见问题与兼容旧项目

| 情况 | 处理 |
|---|---|
| 找不到项目或认证失败 | 核对服务器 HTTPS 地址、项目身份、自己的编辑权限；重新安全登录 |
| 本地目录已有原稿 | 先备份两侧；在空子目录首次拉取或审核差异，不覆盖 |
| Socket.IO/TLS/编译失败 | 核对服务器版本、反向代理的 WebSocket 支持、网络及编译日志；不关闭证书校验 |
| 两端同时修改或同步中断 | 暂停并比较双方内容；由 Agent 使用恢复流程，不盲目重试 |
| 旧教程提到 VS Code | 新 CE 项目可以跳过全部插件步骤；直接使用本指南 |

**已有 Overleaf-Workshop 或 Git Bridge 用户**：保留工作正常的旧绑定，只有明确要求时才继续使用旧通道或迁移。迁移前备份并核对两端内容、暂停旧同步引擎，审阅旧基线及恢复状态，再建立新 CE 绑定。Git Bridge 仅在服务器实际提供该能力时可用；不静默切换，不同时启用两个同步引擎。Workshop 专用操作见 [兼容手册](OVERLEAF_AGENT.md#1-先复用实际环境overleaf-workshop-兼容通道)。

## 8. 实现与验证范围

内置 CE 源码为 `research_workspace/overleaf_ce.py`，相关命令及模拟协议/传输测试见 `publication_cli.py`、`overleaf.py` 和 `tests/test_overleaf_ce.py`。2026-11-25 的说明更新未实际登录实验室服务器；真实认证、收发、远端编译及不同 CE 版本的兼容性应在自己的环境中分别验收。维护者和 Agent 请参考 [内置 CE 执行手册](OVERLEAF_AGENT.md)。自然语言入口统一以上述步骤为准。
