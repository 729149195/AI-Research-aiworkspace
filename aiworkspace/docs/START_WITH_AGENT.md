# 用自然语言使用 AI Workspace

## 第一次只做一件事

把这个仓库交给你正在使用的 agent，或者在支持本地文件的 agent 中打开仓库文件夹，然后说：

> 请阅读 README，按 AI Workspace 的使用入口显示功能菜单，带我开始使用。操作由你完成，需要我确认的地方再问我。

你会看到新建、改稿、文献、想法、分析图表、Overleaf、转投、审查、进度和设置十个入口。回复编号或直接说需要做什么。目标明确时，直接说“帮我改摘要”即可。

[菜单预览](../MENU.md)

菜单可以在环境安装前显示。agent 会在真正需要操作文件时检查运行条件。首次准备环境可能需要你确认安装；无需自己打开终端或填写配置代码。有的宿主会弹出工具授权框，在核对操作范围后确认即可。

## 日常对话例子

**你：** 选 1，我想开始一篇会议论文。  
**agent：** 论文主题和作者怎么称呼？目标会议已经确定了吗？暂时未定也可以先建立项目。  
之后由 agent 查官方模板与规范、整理目录和填写结构化资料。真实年份、track、匿名要求等还不明确时，它会集中确认。

**你：** 直接把讨论里的“导致”改成“相关”，摘要也检查一下。  
agent 会读取当前稿件、处理修改、保存改动记录，并检查相关论点及其他章节。已有授权范围内的常规整理不用反复确认；证据强度或未解决的科学判断仍会单独指出。

**你：** 帮我连接实验室 Overleaf。  
agent 会使用项目已保存的地址，或提出默认自建服务器。你在本机插件／网站登录，agent 继续完成支持的配置与检查。密码、cookie、token 不要放在聊天里。远端上传要确认具体项目和稿件范围。

**你：** 更新这个 Workspace，但保留我的论文和修改过的规则。  
agent 先预览更新，向你说明影响；确认后执行增量升级，处理本地冲突并给出结果。你无需重新创建论文。

这些是交互示例，实际操作结果要以 agent 的工具执行回执为准。

## 常用表达

“菜单”回到功能入口；“继续”接着实际未完成的工作；“查看进度”显示当前论文的待办；“返回”停止当前尚未执行的步骤；“切换论文”选择另一个项目。已经执行的修改会明确说明，返回菜单不会自动撤销。

“项目与设置”还包含打开已有论文、接入旧 LaTeX 稿、更新、环境检查和自动沉淀。旧稿会保留原文件；接入位置不明确时会先确认。不要把真实论文放进公共框架仓库。

## 哪些地方仍需要你

研究目标和重要结论由你判断；首次安装、外部上传、费用、覆盖冲突等需要你确认具体范围；账号在本机登录；来源核验和独立审查需要实际完成。agent 负责技术操作和整理，不代替真实审核或虚构身份。

普通网页聊天通常不能读写你电脑上的项目。此时仍能显示菜单、讨论想法和修改你提供的文字，持久保存、同步和编译需要切换到具备对应权限的文件型 agent。宿主是否自动读取入口取决于其实现；没有显示菜单时，发送第一节那句话即可。这里的菜单是聊天中的文字选择，没有单独安装的图形客户端。

## 给旧项目的唯一一句话

> 请先检查当前框架版本，帮我增量升级并启用菜单入口，保留论文、已填写内容和本地定制；更新前把需要确认的内容集中告诉我。

框架 0.4.0 会给旧项目增加 workspace-guide 和菜单文件。更新发生冲突时保留你的修改并让你决定；不要重新初始化已有项目。

具体实现和命令留给 agent 或开发者阅读：[Agent 操作手册](AGENT_PLAYBOOK.md)、[增量更新](UPDATING.md)。
