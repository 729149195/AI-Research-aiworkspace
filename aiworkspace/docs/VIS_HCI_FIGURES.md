# VIS / HCI 学术配图：解释研究对象与机制（0.6.1）

## 用户继续用自然语言

菜单仍是 5。可以直接说：“按可视化／人机交互论文的方法图来画，用同一个例子解释输入、关键操作和输出；先给我看图，不要画成通用软件架构。”

agent 应读取已有稿件、图表目的、期刊尺寸和用户参考，查看相近研究的实际图与图注，列出分图的研究对象，再生成有具体内容的矢量图版。图源和技术执行由 agent 维护，用户不填写代码、JSON 或布局坐标。

## 本次纠正

0.6.0 的节点、分组、箭头引擎适用于简单流程与工程结构。那些模板的渲染测试不代表它们已经充分表达了 VIS/HCI 论文的方法。只改变颜色、圆角或图标无法补足研究内容。

本次把 `research-diagram` 的默认流程改为：先选图的职责，再确定同一个可追踪例子，展开真实对象、编码、变换和交互反馈；让关键贡献占据视觉空间。方法总览、编码解释、交互叙事、真实界面注释、同条件比较分别设计，避免全都套同一种节点图。

具体查阅过的论文、图号、图像可见范围和设计判断见 [参考阅读与设计指南](../research_workspace/assets/templates/vis-hci-figure-guide.md)。只归档链接和阅读笔记，没有把论文原图或用户上传的参考图复制进公共仓库。它们提供设计参考，不自动成为用户论文的证据。

## 两个原创演示

[方法解释图](../examples/vis-hci/method-detail.svg)：同一批 8 条人工数据，依次显示刷选区域、几何判定、身份集合、布尔掩码、分组计数和联动表格。数据点的字母 ID 与选择状态跨分图保持一致。读者能直接检查选择如何得到，而不只看到“选择模块”。

[交互叙事图](../examples/vis-hci/interaction-storyboard.svg)：显示初始状态、拖动刷选的目标和动作、保留上下文的高亮，以及联动视图的可见反馈。

两图使用同一份 [人工 CSV](../examples/vis-hci/worked-example.csv)。选中的是 b、c、d；A 组 1/4，B 组 2/4。这是一个熟悉交互的解释性练习，没有声称研究创新、用户实验结果或已实现产品界面。它们演示图版表达方式，不要求每篇论文使用这个故事或布局。

## 实现与来源保护

新增 `paper-composite` 路线，在原 `research_workspace.diagrams` 操作中按 kind 选择。agent 自由绘制本地 SVG，保留文字、图形、局部细节、数据示例和分图组；无需先把内容简化为 nodes/edges。每个 panel 必须说明角色、对象、要说明的操作、来源状态及来源说明。

输入采用严格的无活动内容矢量子集：基本形状、路径与文字；不接受脚本、事件属性、CSS、外部引用、位图嵌入、transform、嵌套 SVG、任意命名空间或 DTD。当前路线不能直接导入任意第三方 SVG，也不假装能处理全部截图或排版公式。真实界面截图较多时，应走单独审查的本地排版工具，保持截图原貌及来源；不得绘制一个虚构界面当作已经实现的系统。

SVG 保留为可编辑主源，输出 SVG/PDF/PNG，并冻结 artwork.svg、spec.json、完整 reproduce.py、图注和替代文字。源文件与复现材料放在 workspace/results/diagrams；投稿用图放在 manuscript/figures。每次生成新版本，原图和稿件不覆盖。新路线不承诺生成 drawio 或 DOT；旧的节点图路线保留原有输出。

原图源、生成图、冻结文件或证据改变时会提示过期。`source-bound` 分图需要真实的当前 Evidence 与 Claim；笔记、图标题和“已生成”回执不能代替核验。自由矢量内的箭头与数值含义需要专项人工／agent核对，不能由像素或 SVG 字段自动证明。生成 Figure 仍从 draft 提案开始，并复用原质量门。

## 给 agent 的内部步骤

先填写 [分图计划](../research_workspace/assets/templates/paper-figure-plan.md)，再写到用户论文的 workspace/figures/ 下：SVG 图源与 kind=paper-composite 的规格。用户无需接触这些文件。

规格实例见 examples/vis-hci/*.json。`artwork` 在论文项目中改为 `workspace/figures/实际图源.svg`；claims/evidence 填实际已有 ID，演示保持空列表。`panels[*].id` 必须对应 SVG 中的分图 g 元素。分图不能只有文字标签；结构验证也无法替代内容设计检查。

沿用 diagrams 的 render 预览、授权生成、check 和 propose。`--svg-only` 可以只生成矢量源；PDF/PNG 复用可选 CairoSVG 依赖，新的自由图版路线不需要 Graphviz。既有节点图仍需要 Graphviz。正文、用户图和已填写计划都不纳入框架默认资产覆盖目标。

## 实际图形审查

在最终栏宽查看实际 PDF：分图和图注对应吗？身份和颜色有没有改义？关键操作能被看见吗？截图或草图的状态是否清楚？是否仍有标题遮盖、乱码、线条冲突或过多空白？去掉模块标题之后，图中能否看见真正被处理的对象和变换？

程序检查 SVG 安全子集、分图对应、物理尺寸、最小文字尺寸、文件和证据完整性。它不输出“学术美观分”，也不认证创新性、科学正确性、无障碍或投稿合规。实际样例与测试范围见 [本轮验证](../verification/paper-composition/README.md)。
