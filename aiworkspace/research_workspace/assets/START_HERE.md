# 从这里开始：和你的 agent 说需求

这是你的论文项目。`workspace/` 保存研究逻辑、证据、规则与改动记录；`manuscript/` 保存正式稿件。你可以用自然语言操作，不需要手动输入程序或维护状态文件。

第一次使用，在能访问本文件夹的 agent 中说：

> 请阅读 AGENTS.md，显示 AI Workspace 功能菜单。操作由你完成，需要我确认的地方再问我。

菜单文件：`workspace/templates/workspace-menu.md`（让 agent 直接显示）。

可以回复编号，也可以直接说“帮我改摘要”“找支持和反驳这个论点的文献”“连接实验室 Overleaf”“把论文转投到另一期刊”。说“菜单”返回入口；说“继续”接着实际未完成的工作；说“项目与设置”打开旧稿、切换论文、检查环境或更新。

Agent 会先读取当前论文，沿用已经保存的信息，只询问缺少的必要内容。首次运行可能需要确认安装或选择目录。目标清楚后，常规修改和整理在本轮授权范围内进行，改动由 auto-route 沉淀。

## 仍然由你掌握

重要研究判断、冲突取舍、软件安装、外部传输、费用和远端写入需要明确范围。账号在本机网站或插件登录，不要把密码、token、cookie 发进聊天。原文核验和独立审核需要真实完成，菜单选择不会替代审核。

已填写的研究想法在 `workspace/research/idea-evaluation.md`，个人规则在 `workspace/rules/project-policy.md`。你可直接让 agent 通过问答协助填写。`workspace/templates/` 是空模板与菜单的框架资产，不在这里填写真实研究内容。

已有论文升级时对 agent 说“帮我更新 Workspace，保留论文和本地定制”。保留 `.rw/framework.json` 和完整研究备份；不要重新初始化论文。

普通网页聊天可以显示菜单并讨论提供的材料；没有本地工具时无法保存改动或实时同步。Agent 应清楚说明已执行与未执行的部分。
