# Research figures for VIS / HCI

## Inputs

Read the selected manuscript, figure purpose, venue/phase/size, Claims and relevant evidence, the user's reference images, and existing figure/diagram briefs. In a paper project read `workspace/templates/vis-hci-figure-guide.md` and `workspace/templates/paper-figure-plan.md`; in the framework use the same files under research_workspace/assets/templates. Reference papers guide visual explanation; they supply no evidence for the user's study. Keep the original Idea Evaluation questions about encoding, task, interaction procedure, visual cues, rationale, alternatives and each figure's purpose.

## Workflow

1. **Name the figure's research job.** Decide whether it is a method overview, encoding explanation, interaction sequence, annotated system view, design-space/comparison figure, result figure or genuinely a software architecture. For a VIS/HCI method figure default to a content-rich composite. Graphviz's seven templates are optional for explicit graph/engineering requests. Do not silently send a paper overview through the generic node-link renderer. Adding rounded rectangles, stock icons or a journal-named palette does not solve missing research content.
2. **Study relevant visual references.** Use the supplied image first. When needed, inspect 2–4 relevant original paper figures AND captions at readable size; record paper, figure number, PDF page, role, specific visual devices and what can transfer. Use the maintained guide to start, then read the user's actual domain. Distinguish an inspected figure from abstract-only reading. Do not copy screenshots or paper artwork into the user's figure without appropriate permission, and do not treat a reference authoring system as a dependency to install.
3. **Extract the actual method before styling.** Internally list the input object, representations, operations, technical novelty, user actions and observable outputs. Select a small, faithful worked example that can be traced end-to-end. Existing data and screenshots are preferred; illustrative values must be labeled and must not masquerade as results. If the manuscript is missing, ask for its method description or prepare only a clearly labeled illustration. Do not invent matrices, losses, embeddings, network layers, salience scores, users or accuracy gains just to fill space.
4. **Build a paper figure plan.** Assign (a), (b), (c)… according to explanatory roles. Each panel states what the reader must learn, the concrete object shown, the visual operation and its source/status. A typical overview can show input marks, an expanded key operation, an intermediate representation, and a real output/example. Panel sizes follow information needs; an unequal two-level layout is often useful. Do not force every paper into four panels, impose a quota of icons, or turn every stage into a labelled card.
5. **Make the mechanism visible.** Draw actual marks/glyphs, selections, row sets, geometry, matrix entries, formulas, layout changes, cropped views or action/state pairs as appropriate. Follow the same example and IDs across panels. Repeat the same glyph, colour and label for the same entity. Show why the novel operation matters with a faithful local before/after or alternative, not a generic “AI/model” icon. Arrows must identify what is transferred/transformed or which action occurs. A mini-chart is meaningful only when its values have an explicit source or an illustrative label.
6. **Author the composition rather than forcing graph layout.** Create editable local SVG primitives or use an authorized vector editor/source-specific script. For the bounded vector route, save SVG under workspace/figures/, write kind=paper-composite with panel sources, then use the existing diagrams render command. Exact fields are in the maintained guide; the agent writes all code/JSON. Actual screenshots should remain authentic assets; the current inert SVG subset does not embed images. Use a separately reviewed composition workflow for screenshots instead of redrawing a fictional interface and presenting it as implemented. Do not route screenshot-heavy work through a box template to evade this limitation.
7. **Typeset for a paper page.** Prefer compact subfigure labels, restrained rules/dividers, purposeful whitespace and a small semantic colour vocabulary. Minimize card chrome, heavy full-panel fills, giant headings, shadows, decorative gradients, capsule labels and cloud/database/brain icons. Select readable fonts and final physical dimensions from the venue; do not impose 7 pt as a universal venue rule. The composition checker uses a configurable minimum as a local sanity check. Complex typography/formulas need a verified local vector/typesetting path; do not fake notation with unrelated glyphs.
8. **Inspect and revise the actual exported figure.** Open the final PDF/PNG at publication width. Check (i) the input is recognizable; (ii) the key operation is visually explained; (iii) an example can be traced across representations; (iv) user action and system response are distinguishable; (v) colour/shape/labels remain consistent; (vi) details, arrows and captions agree with the manuscript; (vii) text and insets remain legible. A clean graph with no collisions can still fail all research-explanation criteria. Revise composition when it fails; do not report “publication-ready” based on successful SVG/PDF export. Keep visual review pending if the host cannot inspect images.
9. **Preserve source and scope.** The paper-composite lane freezes artwork.svg, spec.json, reproduce.py, caption and alt text outside the manuscript upload subtree; exports only diagram.svg/PDF/PNG there. Existing diagram records track the original artwork, files and linked nodes. Run check and create only a draft Figure proposal with the original workflow. Human visual/scientific review is still needed; vector pixels do not automatically encode or prove causal semantics. Source-bound panel declarations require actual current verified project Evidence, with further per-panel relevance checked by the specialist.
10. **Deliver the figure, quietly.** Show the preview and the one or two substantive design decisions. Let the user say “展开这一步”“换成真实截图”“突出这里的编码”“不要这些大框”. Preserve prior versions, update the caption and related text, and use auto-route. Users need not choose a renderer, name this Skill, tune parameters, fill profiles or operate a terminal.

## Outputs

A content-rich figure with readable panels, concrete research objects, worked-example continuity, meaningful annotations and an explanatory caption. Supply editable source, local reproduction material, truthful provenance and outstanding reviews. Use a paper-figure plan as working context, never as evidence. The pure-vector composition route exports editable SVG/PDF/PNG; it does not fabricate drawio/DOT for freeform artwork. The optional graph route retains those older outputs.

## Boundaries

Do not invent science to make a diagram look academic. No stock-icon pipeline as the default VIS/HCI overview, no fabricated embeddings or pseudo-interface screenshots, no unsupported effect sizes or novelty claims. No blanket “Nature/IEEE/CHI compliant” visual presets. No silent uploading, paid generation, arbitrary SVG execution or font redistribution. The restricted compositor rejects scripts, CSS, external URLs, images, transforms and nested viewports; other assets require a separately reviewed workflow. Reproduction is export reproducibility; semantic correctness and aesthetic quality are independent judgments.

## Evaluation

For a method-only request, obtain the actual method or label a worked example as illustrative. A supplied paper reference leads to analysis of object/operation/panel logic rather than copied colours. A brushing example must select the same row IDs in plots, masks, linked counts and tables. An interaction storyboard must show the action target and actual state changes. A generic box diagram is acceptable when the requested object really is an architecture graph, but cannot stand in for missing scientific explanation. Changing the original SVG, frozen source, metadata, output or evidence makes the record stale. Pure menu browsing is read-only, and prior graph records remain checkable. These tests do not establish universal host adherence or journal acceptance.
