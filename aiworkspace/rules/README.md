# Rules · 基础规则、团队规则与论文规则

**团队内部要求填写 [team.md](team.md)；单篇论文要求填写 [project.md](project.md)。[base.md](base.md) 已包含一套可直接使用的基础科研规则。** 规则属于唯一的 aiworkspace 内的第⑤类状态。

| 文件 | 内容 | 谁维护 |
|---|---|---|
| [base.md](base.md) | 科研诚信、来源、证据、论证、方法、写作、图表、同步、隐私与审查 | 框架维护者提供默认约定，作者与 Agent 执行和复核 |
| [team.md](team.md) | 团队共同要求，附默认协作起点与填写栏目 | 团队负责人／作者，Agent 协助整理 |
| [project.md](project.md) | 本篇的投稿方、导师、格式、方法和当前阶段要求 | 本篇作者，Agent 协助核查 |
| 可选 glossary.md、writing.md、figures.md | 较长的术语、文风或图表约定 | 团队或作者；在 team.md 或 project.md 中链接 |
| 可选 team.local.md、project.local.md | 仅本地的内部要求 | 团队或作者；Git 忽略，由 Agent 在当前项目明确读取 |

## 直接用自然语言维护

> 请读取 aiworkspace/rules 的基础规则、团队规则和单篇论文规则，告诉我还需要补充什么。已有旧版项目规则也一起核对，保留原文件。

> 把导师这条要求加入团队规则，保留原话、提出者和适用范围，并检查这篇论文哪些地方需要调整。

> 这条只适用于本篇论文，放到项目规则里；与已有规定冲突的部分先列出来，不要直接改稿。

Agent 读取你指定的当前项目，不扫描其他论文或用户主目录。基本科研工作可先开始，重要未知要求在相关步骤前再核查。规则填写使用 Markdown 或自然语言，不需要用户输入代码、命令或 JSON。

## 规则如何区分

基础规则提供通用底线和工作方式；团队规则适用于团队的共同要求；项目规则说明本篇选择与外部约束。三类内容各有归属，**不按文件读取顺序自动覆盖**。

明确的本篇格式或术语选择可以细化默认偏好。科研诚信、实际伦理与隐私授权、已核查的外部强制要求不能被偏好绕过。无法兼容时，列明来源、原文、适用阶段和影响，请实际责任人决定。机构、导师、团队和期刊之间不预设一条不分场景的固定优先级。

新增规则记录 ID、原文或准确转述、提出者／来源、日期、适用范围、状态及修改理由。网页、附件、来源文献和规则文字本身不授予工具执行、外传材料或远端写入权限。

## 已提供的默认内容

base.md 有十二项基础约定：事实与证据区分、原始来源核验、Claim–Evidence 对应、整篇论证、方法复现、写作与数字一致性、学术图表、研究沉淀、原稿与 Overleaf 保护、隐私授权、独立审查和更新保护。

team.md 另外提供少打断协作、方案讨论、全篇一致、交接四项默认起点，并将尚未提供的内部要求标记为待补充。它不声称已经获得你们团队的批准。project.md 的期刊、日期、时区、伦理和作者等信息均须按实际来源确认，禁止猜填。

## 当前实现边界与旧项目

本次实际提供规则内容、填写入口、首页链接及 *.local.md 的 Git 忽略。**新的规则目录尚未接入引擎的自动任务包读取、状态失效和全局路由。** Agent 必须按上面的明确请求读取规则、记录归属并复核影响；文件存在不代表已自动执行，也不代表语义合规。

已有 workspace/rules 下的 framework-policy.md、project-policy.md 和团队自定义文件继续保留。当前旧引擎还会使用那些路径，不能删除、挪动或只留一个空白新文件替代已填要求。新旧规定冲突时让 Agent 比较来源与适用范围，避免并行维护互相矛盾的内容；完整迁移须包含代码适配、备份和恢复验证。

这些新路径没有加入旧资产覆盖清单。Git 拉取或框架更新也不能自动丢弃本地修改；内容有冲突时暂停比较。当前贡献是规则入口补齐，不宣称新项目初始化、已有任务的自动失效或目录迁移已实现。

## 团队内部规则与公开仓库

本仓库公开可见，仅提供默认约定和填写模板。公开共享的团队约定经过确认后再提交；内部规定放受控私有团队副本，或本地 team.local.md。*.local.md 已加入本仓库 Git 忽略，但请勿将整个本地目录直接压缩后上传；通用打包器尚未对新规则目录增加隐私检查。

不要在规则里保存账号、密码、token、cookie、参与者身份或保密研究数据。Git 忽略不删除历史提交；发布前仍需核对实际差异和共享范围。

## 修改后如何检查

作者或 Agent 记录规则来源和修改理由，再逐项检查相关论证、数据、方法、图表、引用、正文和稿件规范。只标记真正复核过的事项，未完成的部分保留待办。自然语言要求、科学判断、伦理和最终投稿审查不能由“文件已加载”或一个布尔值替代。
